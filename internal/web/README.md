# laneway web

`laneway web` (alias `serve`) serves the board in a browser. Flags: `-addr 127.0.0.1:8484`, `-remote`, `-no-open`, `-demo`; global `-site` / `-config` as usual.

- Server: Go, `internal/web`. One file per area, `api_<area>.go`, each registering routes in `init()` with `get/post/put/del("/path/{param}", func(ctx, s, r) (any, error))` (see `server.go`). Handlers wrap `s.Client()` (`*jira.Client`) and return its structs as they are: JSON keys are the Go field names (`card.Key`, `issue.Summary`). Zero times arrive as `0001-01-01…` (`fmt.isZero`). Errors become `{error}` with a status. Writes must be POST/PUT/DELETE.
- Frontend: `internal/web/static`, plain ES modules, no build step, no dependencies, embedded in the binary. Pure modules (no DOM) get node tests in `jstest/*.test.mjs`, run by `go test` when node is installed. Go: `go build`. JS: edit and reload (run `go run . web -demo -no-open` and open http://127.0.0.1:8484; the `-demo` project needs no Jira).
- URLs: plain paths (`/board/ABC/1?issue=ABC-1`, `views/index.js`), every write through `app.go`/`setURL`/`setQuery`/`panel` (`app.js`, `lib/nav.js`), never `history` or `location` directly. The server answers any path without an extension outside `/api` with the shell (`appPath`); assets are linked absolute. An old `#/…` link is rewritten to its path.
- Themes: only CSS variables from `css/themes.css`; never raw colours. Density via `--pad --row --fs`. `ui.theme` (a preset name, or `{preset, accent}`) is the default until the browser picks its own theme or accent; its colours by name stay the TUI's.
- Icons: Lucide, only those used, in `lib/icons.js` (`icon(name, fill)` → `<svg class="ico">` in `currentColor` at the text's size; `setIcon(el, name, text)` redraws only on change; licence in `vendor/lucide/`). To add one, copy the inner markup of lucide-static's `icons/<name>.svg` into its table; `icons_test.go` fails on a missing or unused one. Plain-text labels (palette rows, picker items, toasts) and the TUI keep Unicode glyphs.
- Text: every word shown goes through `T('…')` / `Tn` (`lib/i18n.js`; Go: `i18n.T`), a literal English key; its Dutch goes in `internal/i18n/nl/*.json` (`go test ./internal/i18n` lists what is missing).
- Keyboard first: every action has a key, registered on a `keys.scope` so `?` lists it.
- First start: without a usable site `webcmd.go` serves `Options.Setup` (`api_setup.go`): only `GET /api/session` (`{setup}`) and `POST /api/setup` answer, the rest 503. `app.js` mounts `views/setup.js` instead of the app; on a save the server is replaced by the app on the same address and the page reloads. `FieldError` refusals arrive as `fields` on the `ApiError`.
- Start at login: `Options.Autostart` (`api_autostart.go`, `internal/autostart`: systemd user unit / LaunchAgent; enable installs for the next login, disable removes and leaves the running one) is set by `webcmd.go` except for `-demo` and `-remote`. `session.autostart` is `{enabled, path}` or null; `PUT /api/autostart {On}`; the setup form's `Autostart` turns it on after a save.

## Shell API (`js/app.js`, `window.laneway` in the console)

```
app.api      get/post/put/del/swr   (lib/api.js; swr(path, onData) answers from cache first)
app.bus      on/emit                issue:changed {key, what?} after ANY write (board/panel refetch; what: "ABC-1 → Done" for a change made, refine lists these), panel, route, focus
app.keys     scope(name) → {bind(spec, fn, desc, {input,hidden,group}), dispose()}   (lib/keys.js)
app.ui       toast errToast modal pick prompt confirm avatar chip statusPill          (lib/ui.js)
app.commands register({id,title,group,run,when}) → unregister                         (palette lists these)
app.go('/board/ABC/1'[, {replace}])   a step back undoes; the route shown, bare (g b on the board), is none; the open panel comes along (?issue=)
app.back(fallback)     the previous entry when laneway made it, else fallback in its place (esc on a page)
app.setURL(url[, {push}]), app.query(), app.setQuery(patch[, {replace}])   the view's own place, no remount
app.marked   () → keys the view has marked (x), set by the view in mount, null after a route change
app.listed   () → the cards the view shows, in order (refine queues them; without it, the keys drawn)
app.panel    open(key[, {card, push, replace}]) / close([{replace}])    the right-hand issue panel, ?issue= on every route (a typed key opens): opening, closing and a link followed are steps back undoes; another issue of the list beside (cursor, [ ]) replaces, {push} makes it a step (a jump) (js/views/issue.js: mountIssue(el, key, {app, full}) → cleanup)
app.actions  edit(key, field[, anchor]) transition(key) create({project,parent,type}) palette(mode) jump() bulk(keys)
app.prefs    get/set                per-site prefs on the server, mirrored to localStorage
app.session  {site, sites, demo, baseURL, me:{AccountID,DisplayName}, projects, ui}
app.chrome   add(el, order) tray item · crumb(title, onclick) → button · label(btn, ...parts) · menu()   (lib/chrome.js)
```

A view is `export default function mount(el, {app, params, query, scope, context, toolbar}) → cleanup?`; `scope` is its key scope (auto-disposed). Routes: `js/views/index.js`.

Chrome (`css/chrome.css`, `lib/chrome.js`), two bars:

- App bar, the same on every route: brand and site (`@`), the views grouped Project / You / Tools, the tray, search. At the right your avatar (`lib/account.js`): a click opens Settings, Keyboard help and the site switch; on laneway-server My sign-in and passkeys, API tokens and apps (`/settings?row=tokens`) and, when you administer the site or a project, Server admin (`GET /api/account`); hosted, Sign out. Settings > Account (`views/settings_account.js`, `GET /api/me`): on laneway-server your avatar (upload, remove; the button redraws on bus `me`), mail (off, at once, hourly, daily), time zone, mail language, sessions (sign out everywhere) and the server's page for password, two-step and passkeys; mail and sessions an app's sign-in can't reach stay away; on Jira a link to your profile. Views that don't fit fold into More (`M`, every view with its key); the open one always stays. The tray shows only what needs you: offline, queued writes, agents waiting (or working), the running timer. Libraries add to it with `app.chrome.add(el, order)` (lower sits further left) and hide their item when quiet; never append to `#top`.
- View bar, the view's own: `context` holds where you are (project / board / sprint switchers: `app.chrome.crumb` + `label`), `toolbar` how you look at it (filters, modes, actions). Both are cleared on route change; the bar keeps its place while the next view mounts and hides when both stay empty; a route that never has controls sets `bar: false` (`views/index.js`) to hide it at once.
- Project and board are one context for board, planning, reports, roadmap, standup and the create dialog (`views/plan_ctx.js`: `resolve`, `setCtx`, `switcher`; prefs `project` and `board.last.<project>`). Routes without params use the remembered one; project and board are separate crumbs: `alt+p` switches the project (to its remembered board, no prompt); in its picker `ctrl+s` or a row's star stars a project (`jira.projects`, per person when hosted: first in the picker, the first opens at start), `B` the board (project-only views: `B` is the project too).
- After a chord prefix (`g`) a hint lists what can follow.
- Key bar (`lib/keybar.js`), one line at the bottom: the main keys of the focused panel, else the view, then the global ones, from `keys.active()`; a bind opts in with `{bar: 'label'}` (binds sharing a label are one hint: `H L move`). A click presses it; hints that don't fit drop from the view's end. A plain toast (no action) shows in it while it lasts. Pref `keybar` (`show`/`hide`, Settings > Appearance, palette); hidden on phones.

## Conventions

- Performance is a feature: render from cached data first (`api.swr`), patch DOM instead of rebuilding, virtualise lists over ~150 rows, delegate events, no layout thrash, no dependencies. Optimistic updates for moves/edits, rolled back with a toast on error.
- After any write call `app.bus.emit('issue:changed', {key})`.
- Mouse works, keyboard is complete. `j/k` and arrows move, `enter` opens, `esc` backs out, `x` selects, `?` shows keys.
- CSS per area in `css/<area>.css`, linked in `index.html` (render-blocking: a sheet added on first use paints its view unstyled for a frame); `css('board')` from `lib/css.js` adds one that is not. Scope selectors to the area: every sheet applies everywhere.
- No layout shift: reserve the room of anything that arrives later (charts their height, the panel head from the view's card), and fill the view bar in `mount` synchronously.
- Reference for behaviour: the TUI in `internal/ui` (keys in `internal/ui/keys.go`, guide in `docs/guide`).
- Parity with the TUI is tested in `parity_test.go`: every TUI action (`ui.keys` name) has a binding in `lib/keymap.js` or a `tuiOnly` reason, on the screens the TUI has it on (`internal/ui/keys.go` `keyScopes`; else an `elsewhere` reason), a web feature without a TUI action gets a `webOnly` reason, and every `ui:` option is in `sharedOptions` or has a `terminalOnly` reason. Logic both need lives outside the front ends, or in an exported `internal/ui` function both call (`ui.JiraConfig`, `ui.ValidateUI`), never copied.

## Settings, remapping, phone

- `GET /api/settings` lists every `ui:` option (type, default, value, doc, choices, restart) from `internal/config/schema.go`, the table the terminal's settings screen uses; `PUT /api/settings/{name}` (`{Value}` or `{YAML}`, empty resets) validates like startup and writes through `config.SetUI` (comments kept). Needs `Options.ConfigPath` (demo gets a temp file).
- Settings page (`views/settings.js`): four groups, in order: Web app (Appearance, Fonts, Board, Notifications; prefs saved on the server, so every browser gets them), Jira and server, the config file's `ui:` topics, Keyboard (one row per key group, folded; the filter finds keys in folded ones). From 1100px a sticky sidebar lists the sections and marks the one in view.
- Settings > Jira site and Server (`views/settings_site.js`): Projects ticks the site's projects in a picker, `PUT /api/site/projects` (`{Projects}`) writes `jira.projects` or `sites.<name>.projects` through `config.SetProjects` and the session follows; Restart, `POST /api/restart`, serves the app again with the config read anew (`Options.Restart`, same address, site and `-remote` token) and the page reloads once it answers. A saved *restart* option's toast offers it too.
- Key remaps: `lib/keys.js` gives each bind an id `scope:defaultKey`. Precedence: the `keymap` pref (`{id: [keys]}`, Settings > Keyboard), then `ui.keys` of the config for binds with a TUI action (`lib/keymap.js` maps scope+key to the action name), then the default. Binds seen are remembered in localStorage (`lw:keyreg`) so the settings page lists views not opened this session.
- Typing that missed its field (`lib/keys.js`, `TYPE_RUN`): three different plain keys within 200ms of each other (or two, then one into a field they opened: `laa` in the assignee picker; a chord starts afresh) take back the first keys (modals opened since, `keys.keep({save, restore})` hooks: app.js walks the URL back, the focus), pause plain keys, and `keys.onTyping` offers the text to the last field (`el.lwType(text)` when it has one, the terminal's). Binds with `{writes: true}` (an API write, a new tab, the clipboard, a saved pref) wait 200ms on a plain key; another plain key drops them. The `charkeys` pref (Settings > Keyboard) off turns single-character keys off (WCAG 2.1.4). localStorage `lw:typing` = `off` turns the guard off: the e2e fixture does, but for `tests/typing.spec.mjs` (`{ typing: true }`).
- `/sw.js` (from `static/sw.js`, version = hash of the embedded files) precaches the shell; `/api` is never cached. `lib/notify.js` `notify(title, body, onclick)` is a no-op unless the user turned notifications on in Settings.
- Long-press / right-click on a card, row or planning row opens an action menu (`lib/pwa.js`, `app.actions.menu(key)`; a view adds entries with `app.menuItems = key => [[label, run]]`). `css/mobile.css` (bottom sheets, lane snap, safe areas, contrast, forced colours) and `css/print.css` are global.
- Fonts (`js/lib/fonts.js`, `window.laneway.theme.fonts`; UI in `views/settings_fonts.js`): `--font-ui`, `--font-mono`, `--lig` (font-variant-ligatures), `--lh` on `<html>`; `css/base.css` and every view use only these, never a literal stack. Prefs (localStorage `lw:p:<name>` + `app.prefs`): `font.ui`, `font.mono` (preset id, `custom` or `file:<uploaded name>`), `font.ui.custom`, `font.mono.custom` (any CSS font-family list), `font.ligatures` (`off` or empty), `font.lh`. `boot.js` applies the resolved stacks (`lw:fontcss`) before first paint. Bundled latin woff2 (OFL, `static/fonts/README.md`, licences in `static/fonts/LICENSES/`) are declared in `css/fonts.css` and downloaded only when a stack uses them; the service worker caches `/fonts/` on first use. Uploads: `GET/POST /api/fonts?name=x.woff2` (raw body, max 4 MB, sniffed, 20 files), `DELETE /api/fonts/{name}`, files in `<state dir>/fonts`, served at `/fonts/custom/<name>` (same origin, so the CSP stays). **Terminal**: use `fonts.terminalStack()` (pref `terminal.font`, a CSS font-family, empty = follows `fonts.monoStack()`), `await fonts.ready()` before measuring cells, `fonts.on(fn)` or bus `prefs` `font.*` to redraw, `fonts.ligatures()`. `terminal.font` '' is the bundled JetBrainsMono Nerd Font Mono, `mono` the monospace font; `terminal.size` px ('' = UI size); rows in `views/settings_terminal.js`.

- `ui.delight` (on unless off; `lib/delight.js`): a card moved into a done lane throws confetti from just under the lane head (canvas, 100 paper pieces in the theme colours, out to about a fifth of the screen width each side: launched up, slowed by drag, falling with flutter and flip, gone in about 3s; not with reduced motion), a completed sprint says how its points rank, an empty inbox says all caught up.
- A newer release (`GET /api/update`, the TUI's daily look in the state file; `ui.update_check: off` stops it, a dev build never looks) shows `↑ v1.2` beside the brand and in the palette: a click copies the upgrade command, else opens the release page.
- `ui:` options the browser reads as the TUI does include `empty_fields` (the panel folds empty fields) and `stale_after` (the board refetches when the tab comes back after it). Terminal only: `terminalOnly` in `parity_test.go`, each with the reason.

## Agent terminal

`GET /api/agents/{pane}/terminal` (`api_terminal.go`) upgrades to a WebSocket (github.com/coder/websocket) and runs `herdr agent attach <pane>` on a pty (creack/pty), as the TUI's agent panel does. Binary frames both ways are terminal bytes; text from the browser is `{"type":"resize","cols","rows"}`, from the server `{"type":"exit","status"}`. Close codes: 4001 taken over by another window (one browser terminal per pane, newest wins), 4002 attach exited, 4003 idle 30 min, 4004 8 h lifetime (the browser reconnects). `?takeover=1` passes herdr's `--takeover`. Frames up to 64 KiB, at most 16 terminals. Closing hangs up the attach; the agent keeps running.

**It is shell access.** Only herdr agent panes (`paneAgent`), never a shell of its own. The upgrade goes through `ServeHTTP` (Host allowlist, Origin, Sec-Fetch-Site, launch token) and must carry a same-origin `Origin`; `-demo` refuses it (`demoGate`).

Frontend: `lib/term.js` wraps xterm.js 6 (`static/vendor/xterm/`, MIT, loaded on first use, cached by the service worker on use, never precached): fit, unicode11, web links, WebGL renderer (DOM fallback). Colours come from the theme tokens and follow theme changes; font from `fonts.terminalStack()`. While focused a modal `terminal` key scope passes every key through except `ctrl+\`.

In the issue panel and on the issue page (`views/issue_term.js`, as the TUI's `ui.agent_view: panel`) the Terminal tab shows the issue's agent (first by state, `4` steps through several) under the issue's head. It attaches 150 ms after the tab shows and detaches when the tab hides, the issue changes or the panel closes (another issue opens on Details, as in the TUI), so a board moving the panel along attaches nothing. It follows the agents snapshot: a new pane or a revived one reattaches. Both it and the agents screen use the one terminal per pane: whichever attached last has it, the other says so and `enter` takes it back. Try it without herdr: `LANEWAY_TERM_MANUAL=127.0.0.1:8592 go test -run TestTerminalManual -timeout 0 ./internal/web/` (fake herdr, a local shell as the "agent").
